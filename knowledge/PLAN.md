# План работ: Реестр операторов дронов

_Создан 2026-09-03. Цель — двигаться так, чтобы НЕ переделывать, когда придут документы Нурлана._

## Что за продукт (зафиксировано)
- **Веб-приложение** (не Android/iOS). Кабинеты операторов/заказчиков — тоже в вебе. Мобильные приложения — возможно потом.
- **Адаптивное**: телефон — одна раскладка, десктоп — другая. Обе — в стиле Kaspi (раскладка, кнопки, карточки «слизываем внаглую», стилистика SkyWorker).
- Стек зафиксирован = стек SkyWorker: FastAPI/Python 3.12 + React 18/TS/Vite + PostgreSQL 17 (см. KONSPEKT раздел 11).

## Стратегия против переделок
Строим от каркаса к деталям. Каркас (структура, экраны, модель данных) от документов Нурлана НЕ зависит — он диктуется задачей «маркетплейс операторов». Документы влияют только на наполнение и детали полей, которые меняются локально.

| Что ждём от Нурлана | Что уточнит | Почему НЕ переделка |
|---|---|---|
| Прайсы / КП по услугам | Поля блока «услуги» (цена за га / сезон / разово) | Блок услуг уже в структуре; придут данные — заполним справочник |
| Документы по найму/критериям | Какие поля допусков/требований обязательны | Добавим/включим поля в анкете — структура та же |
| Бренд-бук | Цвета и лого | Чисто визуальный слой (тема), меняется в одном месте |

Вывод: пока строим каркас на нейтральной теме-заглушке и с базовыми полями. Ничего из этого потом не ломается.

## Фазы
**Фаза 0 — проектирование (сейчас, ни от чего не зависит).**
План + первый набросок модели данных + карта экранов. Согласовать с Русланом ДО кода. Это и есть защита от переделок.

**Фаза 1 — каркас приложения.**
БД, регистрация/вход, профиль оператора (базовые поля), каталог операторов + карточка + фильтры. 2-3 демо-профиля. Нейтральная тема.

**Фаза 2 — маркетплейс-логика.**
Кабинет оператора и кабинет заказчика, заявки, рейтинг/отзывы, согласие на ПД.

**Фаза 3 — наполнение по документам Нурлана.**
Блок услуг по прайсам, допуски/критерии по внутренним документам, брендинг по бренд-буку.

**Фаза 4 — подготовка стыковки.**
Заполнение external_id, REST API для обмена с SkyWorker по UUID.

## Первый набросок модели данных (черновик, Фаза 0)
Все id — UUID. Поля `external_*` пока пустые — задел под стыковку.

**operators** (профиль оператора)
- id (UUID), external_user_id (UUID, null — под их users.id)
- ФИО, фото, телефон, whatsapp, email
- тип: `наёмный` / `услуги` / `оба`
- region_id (UUID, под их regions.id), город
- о себе (текст)
- рейтинг (число), кол-во отзывов
- статус верификации
- согласие_ПД (bool), согласие_маркетинг (bool)
- создан/обновлён

**directions** (справочник направлений) — агро, геодезия, инспекция… (расширяемый)
**operator_directions** — связь оператор↔направления (многие-ко-многим)
**skills** / **operator_skills** — навыки
**permissions** (допуски) — категория (1/2/3), свидетельство внешнего пилота, кем выдан, срок, статус проверки; привязка к оператору
**equipment** (оборудование, если тип «услуги») — модель дрона, кол-во; привязка к оператору
**services** (услуги оператора) — направление, описание, единица (га/сезон/разово), цена — наполним по прайсам
**portfolio** — фото/видео/кейсы оператора
**reviews** — отзыв, оценка, автор, дата
**customers** (заказчики) — организация (external_org_id под их organizations.id), контактное лицо, регион
**requests** (заявки на оператора) — заказчик, направление, регион, тип (найм/услуга), описание, бюджет, статус

## Первый набросок экранов (черновик, стиль Kaspi)
**Публичные (без входа, гостевой просмотр):**
1. Каталог операторов — сетка карточек + поиск + фильтры (направление, регион, допуск, оборудование, рейтинг) + сортировка
2. Карточка оператора — фото, рейтинг/отзывы, направления, допуски-бейджи, оборудование, портфолио, кнопка «Связаться»

**Регистрация/вход:**
3. Регистрация (оператор / заказчик), 2-3 шага, согласие ПД
4. Вход

**Кабинет оператора:**
5. Мой профиль (редактирование анкеты)
6. Моё портфолио
7. Отклики/приглашения

**Кабинет заказчика:**
8. Поиск операторов (тот же каталог + избранное)
9. Мои заявки
10. Создать заявку

**Общее:** нижний таббар (моб.) / верхнее меню (десктоп): Каталог / Заявки / Профиль.
